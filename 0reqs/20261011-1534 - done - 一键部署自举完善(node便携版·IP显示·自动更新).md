# 一键部署自举完善（node 便携版 · IP 显示 · 自动更新）

## 需求

上一轮修复静默失败后，用户在真实 NAT 服务器上连续部署试错，依次暴露并要求解决：

1. 服务器无 node：报 `❌ 未找到 node (需 18+), 请先安装`——要求免 root 一键部署不依赖预装。
2. node 下载 404：便携版 URL 拼成 `linux-amd64` 报 404。
3. 修复后重跑仍报旧错：拿到的是 CDN 缓存的旧脚本。
4. 启动横幅不显示服务器 IP：参考 `tuic-hy2-node.js-python/tuic.sh` 的做法（该脚本读 `PTERODACTYL_SERVER_IP` 显示节点链接）。
5. 用户验证发现 server.js 从不更新：`ensure_server_js` 存在即跳过，run.sh 再新也没用，IP 探测代码落不了地。

## 讨论

- **node 便携版策略**：官方 `nodejs.org/dist` 提供 linux x64/arm64 的 tar.gz 二进制，解压即可用、免 root。默认 `v22.14.0`，`NODE_VER` 可覆盖；系统 node ≥18 优先用系统的。用 .tar.gz 而非 .tar.xz 避免老容器缺 xz。注意官方构建需 glibc ≥2.28（Debian 10+/Ubuntu 20.04+ 满足），CentOS 7 类老系统需换 unofficial 静态构建（已告知用户，暂未做）。
- **架构命名差异（404 根因）**：`detect_arch()` 为 cloudflared 返回 `amd64`，但 node 官方包 x86 架构名叫 `x64`，不存在 `linux-amd64` 包（实测 x64=200/amd64=404）。两处命名只差 x86 这一个值，arm64 一致——本机 arm64 验证恰好绕过了该差异，教训是拼 URL 的每个变量都要按目标命名规范核对。修复用 `${arch/amd64/x64}` 转换，cloudflared 仍用 amd64。
- **GitHub raw CDN 缓存**：响应头 `Cache-Control: max-age=300`（实测确认），推送后 5 分钟内重跑会拿到旧脚本——"修复了还报旧错"的迷惑来源。部署命令加 `?t=$(date +%s)` 绕过（raw 按路径取内容、查询串仅参与缓存键，实测有效）。
- **IP 探测链**（对齐 tuic.sh 惯例并加强）：`SERVER_IP` 手动覆盖 > `PTERODACTYL_SERVER_IP`（翼龙注入）> 出网探测（api.ipify.org → checkip.amazonaws.com，3s 超时，正则校验返回确为 IP）> `os.networkInterfaces()` 首个非内部 IPv4 > `<你的IP>` 占位符。横幅改为探测完成后再打印（Promise then）。
- **server.js 更新策略**：从"存在即跳过"改为"每次部署拉最新 + `cmp` 比对、有变化才替换"——部署语义变为"总是最新版"，且 11KB 下载成本可忽略。下载失败但有本地旧版时降级沿用（可用性优先于新鲜度），两者皆无才退出。
- **测试环境踩坑（仅本机，不影响交付物）**：macOS BSD grep 把模式中间的 `$` 当行尾锚点导致 `^PORT=$(...)` 匹配不到，需用 `grep -F`；macOS bash 3.2 的 `source <(进程替换)` 不生效，需先落盘再 source。
