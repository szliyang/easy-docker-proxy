# 一键部署纠错与静默失败改进

## 需求

本项目原为 `szliyang/NAT-Sing-box` 仓库的 `docker-proxy/` 子目录，现已拆分为独立仓库 `szliyang/easy-docker-proxy`。本次两个诉求：

1. 一键部署在服务器上失败，需要纠正。
2. 失败时服务器上没有任何错误信息（输出停在 `📥 Downloading server.js...` 后即消失），需要改进；用户明确：程序运行中显示 verbose 输出即可。

## 讨论

- **部署失败根因**：`run.sh` 的自举下载地址 `RAW_BASE` 仍指向旧仓库子目录 `szliyang/NAT-Sing-box/main/docker-proxy`，拆库后该地址已 404（实测确认：旧地址 404，新地址 `szliyang/easy-docker-proxy/master` 200）。
- **无错误信息根因**：`ensure_server_js` 中 curl 带 `-s`（静默）吞掉错误输出，叠加 `set -e` 在失败时直接退出脚本、一行报错不打印——两者合谋造成"无声死亡"。
- **连带发现的两处同类静默退出点**：
  - cloudflared 下载同样 `curl -Ls --fail` + `set -e`，失败即静默退出；改为失败降级（跳过 Argo 隧道，本地 HTTP 端口照常工作）而非整体退出。
  - Argo 临时隧道域名探测 `argo_host=$(grep ... | head -n1)` 在 `set -o pipefail` 下 grep 无匹配（日志尚未生成域名时每轮都会发生）即导致赋值语句失败、脚本静默退出；补 `|| true`。
- **残留空文件陷阱**：`curl --fail` 失败时可能留下空的 `server.js`，原 `[[ -f ]]` 判断会误判"已存在"而跳过下载；改 `[[ -s ]]`（存在且非空）并在下载前 `rm -f` 清理。下载改走 `.tmp` 临时文件、成功后才 `mv` 落位。
- **verbose 化**：curl 去 `-s` 显示进度条与错误行，加 `--retry 2`；成功/已存在时打印字节数；启动时打印工作目录；node 版本检查提前到下载之前（避免环境不满足还白下载）。
